# 用 AI 从 0 到 1 做一个产品：我的完整工作流

> PRD → 技术设计 → AGENTS.md → 实现 → 测试部署，五步走让 AI 真正成为你的队友。

## 为什么需要文档

很多人让 AI 写代码，上来就是一句「帮我做个 XX」。结果 AI 写出的东西往往和想象差很远，然后陷入无穷无尽的修改循环。

问题不在 AI，而在于**意图没有说清楚**。一份好的需求文档，就是给 AI 的「地图」。

## 五步工作流

### 第一步：需求研究

动手前先花一点时间调研：

- 明确要解决什么问题
- 看看类似产品怎么做
- 记录发现，哪怕只是几行笔记

### 第二步：PRD

把想法整理成正式文档，明确**做哪些、不做哪些**。一份好的 PRD 包含：

- 产品概述与目标用户
- 功能列表与优先级（MVP / 后续）
- 界面设计要求
- 非功能性需求

### 第三步：技术设计（TECH_DESIGN.md）

确定技术栈、项目结构、数据模型与关键技术点。这个文档告诉 AI「用什么技术、代码怎么组织」。

### 第四步：AGENTS.md

在项目根目录创建 AGENTS.md，写明项目是什么、怎么跑起来、有哪些硬性约定。它是跨工具通用的项目说明，Codex、Copilot、Cursor 都能读取。

### 第五步：实现、测试、部署

把三份文档一起喂给 AI，按「基础框架 → 核心功能 → 细节优化」三步迭代。跑通核心后立即用 Git 管理，每完成一个功能提交一次。

## 我的经验

- **拆解任务**：不要让 AI 一次性完成复杂的任务，拆成多个小任务
- **控制变量**：每次只改一个地方，出问题容易定位
- **及时止损**：同一个 Bug 让 AI 改好几轮还不行，Git 回退 + 换思路
- **写测试**：修好 Bug 后让 AI 生成单元测试，防止回归

## 结语

AI 不是许愿机，而是**协作对象**。你给的信息越清晰，它回报的效率就越高。这套流程我已经在多个项目上验证过，从桌面应用、浏览器扩展到网站，都能稳定产出可用产品。
